# 0001. 클라이언트 메모리에서 토큰 관리

- 상태: 승인
- 작성일: 2026-09-28
- 결정일: 2026-09-28
- 대체한 ADR: 해당 없음

## 맥락

로그인 후 받은 액세스 토큰을 여러 클라이언트 함수에서 사용해야 하며, 액세스 토큰의 유효기간은 15분입니다. 현재 애플리케이션에는 서버 세션/BFF가 없습니다.

## 고려한 선택지

### 선택지 1: 모듈 메모리 저장 및 갱신

- 장점: 페이지 사이에서 모듈 API를 공유하고, 토큰을 브라우저 영구 저장소에 남기지 않습니다.
- 단점: 새로고침 후 토큰이 사라지고, 자바스크립트 실행 중에는 XSS로 토큰에 접근할 수 있습니다.

### 선택지 2: localStorage 저장

- 장점: 새로고침 뒤에도 토큰을 복원할 수 있습니다.
- 단점: 자바스크립트에서 읽을 수 있어 XSS 공격에 노출됩니다.

### 선택지 3: 서버 세션/BFF

- 장점: 브라우저에 토큰을 노출하지 않고 서버에서 갱신을 처리할 수 있습니다.
- 단점: 서버 측 인증 프록시와 세션 구성이 필요합니다.

## 결정

현재 앱 구조에 맞춰 메모리 모듈로 액세스 토큰을 관리하고, 만료 30초 전부터 refresh API로 갱신합니다. 공통 `fetchWithAuth` 함수가 페이지별 API 요청에 Bearer 헤더를 설정합니다.

## 결과

- 새로고침 후에는 다시 로그인해야 합니다.
- refresh API가 `POST /api/v1/auth/refresh`이고 쿠키 또는 선택적 refresh token으로 인증된다는 전제입니다. 실제 백엔드 계약을 확인한 뒤 경로와 응답 필드를 조정해야 합니다.
- 장기적으로는 서버 측 세션/BFF로 옮기는 편이 더 안전합니다.
