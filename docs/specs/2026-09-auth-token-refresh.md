# 액세스 토큰 저장 및 갱신 스펙

- 상태: 구현 완료
- 작성일: 2026-09-28
- 담당: Codex

## 배경과 목적

로그인 응답으로 받은 액세스 토큰을 다른 클라이언트 API 함수에서 재사용하고, 유효기간 15분이 지난 뒤 갱신합니다.

## 범위

### 포함

- 로그인 응답의 액세스 토큰, 선택적 갱신 토큰, 만료 시간을 메모리 모듈에 저장합니다.
- API 요청 시 만료 30초 전부터 갱신을 시도합니다.
- 여러 요청이 동시에 만료를 감지하면 갱신 요청을 하나로 합칩니다.
- 공통 `fetchWithAuth` 함수로 Bearer 토큰을 요청 헤더에 전달합니다.

### 제외

- 새로고침 이후 토큰 복원
- 로그아웃 UI 및 서버 로그아웃 API 호출
- 서버 측 세션/BFF 구성

## 사용자 흐름

1. 사용자가 로그인에 성공합니다.
2. 로그인 응답의 토큰이 인증 모듈 메모리에 저장됩니다.
3. 다른 클라이언트 API 함수가 `fetchWithAuth`를 사용해 API를 호출합니다.
4. 액세스 토큰이 만료 임박이면 모듈이 갱신 API를 먼저 호출한 뒤 원래 요청에 새 토큰을 사용합니다.

## 요구사항

- 응답의 `access_token` 또는 `accessToken`을 액세스 토큰으로 인식합니다.
- 응답의 `expires_in` 또는 `expiresIn`(초)을 사용하며, 값이 없으면 15분으로 간주합니다.
- 만료 시각 30초 전에 토큰 갱신을 시작합니다.
- refresh API는 `POST /api/v1/auth/refresh`이며 쿠키 인증을 위해 `credentials: include`를 설정합니다. 메모리에 갱신 토큰이 있으면 요청 본문에도 전달합니다.
- 메모리 저장을 사용하므로 새로고침하면 토큰은 사라집니다.

## 예외 및 실패 처리

- 갱신 응답이 실패하거나 네트워크 오류가 발생하면 인증 상태를 비우고 오류를 반환합니다.
- 로그인 응답에 액세스 토큰이 없으면 인증 모듈이 오류를 발생시킵니다.
- 갱신 API 경로와 필드 형식은 백엔드 계약 확인이 필요합니다.
