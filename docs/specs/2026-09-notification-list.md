# 알람 목록 조회 스펙

- 상태: 구현 완료
- 작성일: 2026-09-30
- 담당: Codex

## 배경과 목적

알람 목록 화면에서 API 응답을 페이지 단위로 조회하고 실제 발송 정보를 표시합니다.

## 범위

### 포함

- `GetNotificationFn`으로 현재 페이지 알람 목록을 조회합니다.
- 헤더의 새 글쓰기는 화면 종류와 관계없이 `/notice/contents/write`로 이동합니다.
- 콘텐츠 목록에서 푸시 알람 설정을 누르면 콘텐츠 ID를 전달해 `/notice/setalerts/write?content_id={id}`로 이동합니다.
- 알람 행을 누르면 알람 ID를 `notification_id`로 전달해 알람 수정 화면으로 이동합니다.
- 목록 번호는 API 전체 건수와 페이지 정보를 기준으로 역순 표시하며 페이지 간 번호를 이어갑니다.
- 제목 열의 제목 텍스트를 셀 가운데에 표시합니다.
- 현재 `page`, `limit`을 query string에 저장하고 진입 시 복원합니다.
- API 결과를 목록 행에 표시할 형식으로 변환합니다.
- API의 전체 건수를 페이지네이션에 연결합니다.
- 조회 실패와 결과가 없는 경우 메시지를 표시합니다.

### 제외

- 알람 목록의 상태 및 대상 필터
- 발송 성공/실패 건수의 별도 상세 조회

## 사용자 흐름

1. 알람 목록에 진입하거나 페이지를 변경합니다.
2. URL의 `page`, `limit` 값을 복원하거나 현재 값으로 갱신합니다.
3. 해당 페이지의 알람 목록을 조회합니다.
4. 조회 결과를 표에 표시합니다.
5. 알람 행을 누르면 해당 알람의 수정 화면으로 이동합니다.
6. 헤더의 새 글쓰기는 콘텐츠 작성 화면으로 이동하며, 콘텐츠 목록의 푸시 알람 생성은 콘텐츠 ID를 포함해 알람 작성 화면으로 이동합니다.

## 요구사항

- 목록 요청에 `page`와 `limit`을 전달합니다.
- query 값이 없거나 올바르지 않으면 `page=1`, `limit=10`을 사용합니다.
- 응답의 알람 ID, 제목, 발송 결과, 날짜, 상태를 행 데이터로 변환합니다.
- 발송 성공·실패 건수는 `stats.success_count`, `stats.failure_count`에서 가져오며 0도 값으로 표시합니다.
- 발송 성공·실패 건수가 없거나 `sent_at`이 비어 있으면 `-`로 표시합니다.
- 상태가 pending 또는 scheduled이면 예약, sent/success/completed이면 발송, failed/failure이면 실패로 표시합니다.

## 예외 및 실패 처리

- 응답 실패 시 표에 조회 오류를 표시합니다.
- 알람이 없으면 빈 목록 안내를 표시합니다.
