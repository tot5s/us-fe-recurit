# 콘텐츠 목록 query string 상태 유지 스펙

- 상태: 구현 완료
- 작성일: 2026-09-30
- 담당: Codex

## 배경과 목적

콘텐츠 목록에서 현재 페이지와 필터를 URL에 보관해 새로고침 후에도 동일한 목록 조건을 유지합니다.

## 범위

### 포함

- 페이지, 카테고리, 상태를 query string에 저장합니다.
- 진입 또는 새로고침 시 query string을 읽어 필터와 목록 조회에 사용합니다.
- 카테고리 또는 상태를 변경하면 페이지를 1로 초기화합니다.
- 헤더의 `us` 로고를 누르면 콘텐츠 목록의 `page=1`로 이동하고 화면 상단부터 표시합니다.
- 목록 번호는 API 전체 건수와 페이지 정보를 기준으로 역순 표시하며 페이지 간 번호를 이어갑니다.
- 제목 열의 제목 텍스트를 왼쪽 정렬하고, 푸시 알림 생성 버튼은 제목 셀 오른쪽에 유지합니다.

### 제외

- 페이지당 표시 개수의 query string 저장
- 브라우저 뒤로/앞으로 탐색 시 목록 상태 복원

## 사용자 흐름

1. 사용자가 콘텐츠 목록의 페이지 또는 필터를 변경합니다.
2. URL의 `page`, `category`, `status` 값이 현재 목록 상태에 맞게 갱신됩니다.
3. 새로고침하면 URL 값을 읽어 같은 필터와 페이지로 목록을 조회합니다.

## 요구사항

- `page`는 1 이상의 정수로 처리하며 값이 없거나 올바르지 않으면 1을 사용합니다.
- `category`와 `status`는 화면에서 제공하는 값만 허용합니다.
- 비어 있는 카테고리와 상태는 URL에서 제거합니다.
- 상태 query 값은 목록 API의 `publish_status` 필터로 전달합니다.

## 예외 및 실패 처리

- 유효하지 않은 query 값은 빈 필터로 처리합니다.
